# Мета-ресёрч kimi: сводная картина и выбор стека

Этот документ — переработка всех шести ресёрчей из `docs/researches/` в одну
картину, с двумя поправками, которых у ресёрчей не было:

1. **Проверка по коду.** Все утверждения, от которых зависит выбор, проверены
   по клонам в `refs/` (SHA — в `refs/pinned.tsv`) и дальше по тексту даны
   ссылками `файл:строка`. Часть проверок уже сделана в
   `docs/analysis/claims-to-verify.md`; здесь добавлены новые (парсер формул,
   семантика `max_attempts`, провайдер `cursor`, устройство extmsg, гейты
   beads). Где новая проверка отменяет старое утверждение — это записано в
   разделе «Поправки».
2. **Ответы из `docs/requirements/open-questions.md`.** Ресёрчи писались до
   них. Ответы уже закрыли часть вопросов, ради которых ресёрчи предлагали
   тяжёлые решения (durable-бэкбон, веб-дашборды, бюджетирование), и
   зафиксировали требования, которых ни один проект не закрывает (контракт
   разрешения findings). Дата прохода: 2026-08-01.

## TL;DR — решение

| Слой | Берём | В каком виде |
|---|---|---|
| Хранение состояния | **beads** | Как есть. Единственный source of truth: граф задач, гейты, ожидания, метаданные |
| Исполнитель | **Gas City** | Как есть + свой pack формул. Формулы, control beads, провайдеры CLI, supervisor, extmsg |
| Методология | **metaswarm** | Контент, не рантайм: промпты, рубрики, роли, шаблон handoff, форматы вердиктов |
| Канал с человеком | **свой Telegram-бот** | Небольшой отдельный процесс: long polling наружу, extmsg/`bd` внутрь |
| Контракт findings | **пишем сами** | Нет ни у кого. Это главная работа и главная ценность системы |

Путь «Gas City + beads + контент metaswarm» совпадает с выводами sol.md и
opus.md, но по итогам этой проверки объём работы **перераспределён**: HITL и
кап циклов оказались дешевле, чем оценивал sol.md (гейты и `max_attempts` уже
есть), а контракт разрешения findings и детерминированный финалайзер —
дороже, чем казалось всем, потому что готового нет вообще ни у кого.

свой store (Forge, Orca с `.orca/progress-*.json`, Temporal с журналом),
либо заменяет beads целиком, либо не берётся. Заменять beads нечем: гейты,
лизинг и `Metadata` в нём уже есть.

### 3.3. Дорого: пишем сами — это и есть ядро системы

Здесь готового нет ни у кого из изученных, и именно здесь смысл продукта.

| Что | Почему нельзя взять готовое | Что учесть |
|---|---|---|
| **Контракт разрешения findings** (Q11, Q12, Q12a, Q17) | Ближе всех Orca (`FixOutcome`), но там полный набор won't-fix = условие останова, а не «ревьюер рассмотрел отказ» (`ReviewLoop.scala:49`); у Gas City и metaswarm вердикт бинарный | Состав из Q11: устойчивая идентичность finding'а **сквозь кругами** (ключ из `findingKey` — про склейку линий, не про круги), `fixed`/`rejected`/`wont_fix`, обоснование отказа, **решение ревьюера по отказу**, провенанс (кто, круг, ревизия). Спор = `rejected` + «настаиваю» → эскалация сразу, если severity выше порога (Q12a) |
| **Детерминированный финалайзер** | В `mol-review-quorum` синтез делает агент; Go-финалайзер намеренно не подключён (`mol-review-quorum.toml:9-11,183`) | Переходы состояния решает код (`reviewquorum.Finalize` или свой): иначе кап циклов — рекомендация. Дедуп и read-only проверка там уже есть, дописать — вердикт и раскладку по контракту findings. Вероятно, первый наш Go-код |
| **Формула цикла проверки с нашей семантикой** | Ни одна готовая формула не различает «не принято» и «спор» и не вешает human-гейт на ветку | Три грабли, найденные проверкой: (1) `max_attempts` в ralph считает итерации run+check **включая первую** (`types.go:686-687`) — для «3 правки автора» (Q13) нужно `max_attempts = 4`; (2) гейт **несовместим** с check/retry на одном шаге (`types.go:1505-1507`) — human-гейт после исчерпания кругов это отдельный шаг/бид, который вешает ордер, прочитавший fail control-бида; (3) check в V0 — только `mode = "exec"` (`types.go:695-696`), значит ревьюер-агент внутри цикла — это exec-скрипт, запускающий CLI и парсящий структурированный вердикт |
| **Техническое обеспечение свежего ревьюера** (Q15) | Везде это договорённость в промпте | Система обязана знать, кто уже видел артефакт (метаданные бидов), и сделать назначение «несвежего» невозможным. Промпт из adversarial-rubric — подстраховка, не механизм |
| **Ревизии артефактов + каскадная инвалидация** (Q7, Q23) | Нет ни у кого | Артефакт привязан к SHA кода явно; правка человеком = новая ревизия, апрувы предыдущей протухают; перезапуск стадии = новая ветка цепочки попыток (`design:A1 → review:A1 → …`), не удаление. До этого перезапуск стадии = перезапуск прогона |
| **Признак живости шага** (Q35) | Таймаут по худшему случаю бесполезно велик | «Думает 10 минут» и «завис» снаружи одинаковы; признак — вывод в стрим / изменения файлов. Лизинг beads с heartbeat (`lease.go:260-288`) — готовый каркас, наполнение — наше |

Промежуточный итог по объёму: готовое покрывает хранение, запуск агентов,
retry, read-only контроль и методологию; дешёвый слой — это недели работы по
конфигам и один маленький сервис (Telegram); дорогой слой — контракт findings,
финалайзер и формула цикла — та самая часть, которой «нет готовой ни у кого»
(open-questions, раздел 0), и она же является причиной писать систему, а не
брать чужую.

## 4. Целевая архитектура (одной картинкой)

```
Ты (терминал + Telegram)
  │  запуск / статус / ответы
  ▼
Наш тонкий слой (Go, поверх gc и bd):
  │  pack формул трёх флоу · финалайзер · контракт findings ·
  │  CLI статуса · Telegram-бот (long polling)
  ▼
Gas City — исполнитель: формулы → control beads (ralph/retry),
  провайдеры claude/codex/cursor, supervisor, extmsg (outbound HTTP)
  ▼
beads — единственный source of truth: граф задач, human-гейты,
  Metadata (артефакты, findings, ревизии), лизинг, DeferUntil
  ▼
CLI-агенты в отдельном клоне проекта (Q8a):
  claude / claude-m / claude-z / codex / cursor-agent
Контент промптов и рубрик — из metaswarm.
```

Q0 при этом закрывается вариантом A (одна кодовая база, два профиля): все
различия РабОрк/СвойОрк — конфиг (куда пишутся артефакты, права push,
worktree-стратегия), ядро общее.

## 5. Почему не альтернативы

- **Temporal / DBOS / Restate / ControlFlow / LangGraph** (главные
  рекомендации fable.md и gemini.md, частично qwen.md). Давали durable-паузу
  «до ответа человека». После находки `bd gate --type human` это избыточно:
  пауза и так durable (состояние в Dolt), а движок добавил бы **второй source
  of truth** рядом с графом бидов плюс требование детерминизма
  workflow-кода. ControlFlow/LangGraph дополнительно про LLM-через-API, что
  противоречит требованию №3 (CLI-агенты).
- **CAO как основа** (qwen.md). Опровергнуто кодом: Telegram отсутствует
  (единственное упоминание — `README.zh-CN.md:44`), плагины observer-only,
  примитива review-loop нет. Ценность — каталог запуска 10 CLI.
- **Microsoft Conductor как мозг** (glm.md). Провайдеры — SDK, не CLI;
  human_gate — локальный TUI/дашборд без внешнего канала; beads и worktree
  отсутствуют. Допиливать пришлось бы ровно то, что у Gas City уже есть.
  Берём только язык контекстных режимов.
- **VirtusLab Orca как control plane** (путь «быстрого прототипа» из sol.md).
  `stopPolicy` при исчерпании итераций сворачивает issue в `ignored` и едет
  дальше — против Q14; внешнего durable-вопроса нет; `stage` внутри fork
  запрещён по дизайну (ADR 0018). Донор контракта findings, не рантайм.
- **Forge** (sol.md, «если Beads не обязателен»). Свой task store = два
  планировщика. Beta.
- **metaswarm как control plane**. State machine физически находится в
  контексте главного LLM: параллельный запуск пяти ревьюеров — это
  `await Promise.all(...)` **внутри Markdown** (`skills/design-review-gate/SKILL.md`),
  счётчик «Attempt 2 of 3» — строка в промпте. Контент отличный, исполнитель —
  нет.
- **Gas Town как основа**. Это чужой opinionated pack поверх gascity; мы
  пишем свой. Читать как референс: эскалации с severity, merge-гейты.

**Уточнения к claims-to-verify.md и open-questions.md (наши собственные):**

8. C7 обещал проверить, «как `bd gate check` узнаёт о разрешении human-гейта».
   Ответ: **никак** — `evaluateGates` обрабатывает `gh:run`, `gh:pr`, `timer`,
   `bead`; `human` попадает в `default: continue` (`refs/beads/cmd/bd/gate.go:651-669`).

   Для нас это не проблема, а конструкция: ответ из Telegram приводит наш бот.
9. «`Timeout` на human-гейте не проверяет никто» — **подтверждено** (читается

10. В `mol-review-quorum.toml` `max_attempts = 3` стоит на **`[steps.retry]`**,

    кругов ревью (Q13). Путаница этих счётчиков уже однажды случалась;
    фиксирую: кап кругов — ralph-control, retry — отдельно.
11. Арифметика капа: ralph `max_attempts` считает итерации run+check **включая

    (Q13) = `max_attempts = 4`. Проверить экспериментом до фиксации пака.
12. Гейт несовместим с check/retry на одном шаге (`types.go:1505-1507`,

13. Пресет `cursor` в Gas City существует, но без one-shot print-режима —

14. extmsg HTTP-адаптер — только исходящий webhook; «Telegram как конфиг»
    (claims-to-verify, C1) уточняется: Telegram — это **внешний процесс**,

15. Манифест: «tutti — ACP как стандарт подключения агентов» — в пинованном

16. Forge: README говорит «public beta 0.1.x», код уже **0.4.0** — всё равно

17. metaswarm «review-JSON-контракты» — это форматы, записанные в промптах

## 8. Порядок проверки до фиксации пака

По убыванию влияния на решение (обновлённый вертикальный срез sol.md с
учётом ответов):

1. **Арифметика капа** (Q13 + п. 11): ralph-цикл с `max_attempts = 4` даёт
   ровно три правки автора; на исчерпании control закрывается fail'ом.
2. **Исчерпание → гейт на ветку** (Q14 + п. 12): ордер читает fail
   control-бида, создаёт human-гейт; **независимая ветка в это время
   работает**. Это центральный эксперимент.
3. **Вопрос через Telegram сквозь** (Q18, Q19, Q20): агент открыл гейт → бот
   отправил вопрос с вариантами → ответ «A» → `bd gate resolve` → ветка
   продолжилась. Заодно проверяет long polling из WSL2.
4. **Kill оркестратора** (Q38): состояние на месте, ручной рестарт, прерванный
   шаг повторяется, дублей нет.
5. **Read-only ревьюер** (Q26): линия, изменившая файлы, валится
   `readOnlyContractFailure`.
6. **Профиль `cursor-agent`** (Q27a): headless-запуск через пресет с
   дописанным PrintArgs; заодно `claude-m`/`claude-z` как env-профили.
7. **Первый флоу** (Q39): `commit-review` по образцу `mol-review-quorum` на
   реальном коммите, с финалайзером кодом.

Если эксперименты 1–4 пройдут — выбор стека считается подтверждённым, и
дальше работа идёт по разделу 3 снизу вверх: сначала дорогое ядро (контракт
findings + финалайзер + формула цикла), потом дешёвая обвязка.
