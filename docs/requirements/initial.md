## Типовые флоу

Хочу, чтобы можно было задавать несколько типовых флоу. Понятно, что и каждый
флоу внутри не статичен, но набор такой:

1. **Новый проект с нуля.**

2. **Фича в большой существующий проект.**

3. **Ревью коммита.** Тут тоже несколько ИИ смотрят, причём здесь уже можно
   сразу параллельно искать косяки. Потом один из них сливает все фандинги в
   один результат, проверяя их — тоже параллельно. А потом финалочкой — ещё
   один цикл с другой моделью-ревьювером.

---

У меня есть запрос на вот такую систему-оркестратор cli-агентов:

---

1. Передача управления следующему агенту без контекста.
   Но при необходимости писать cut-off файл. Или напротив писать лишь задачу для свежего взгляда.

2. Распараллеливание задач по графу таск-планов (beads)

3. Агенты от разных вендоров, разные CLI-агенты (не просто ЛЛМ через АПИ).

4. При появлении Открытых вопросов - отправка сообщения (не суть как - телеграм/почта/просто дёргается что-то, всегда можно прикрутить канал) и остановка до ответа.

5. Циклы проверки:
   А Сделал - Б проверил - А поправил/написал что и почему не стоит править и так, пока Б не скажет ок (Максимум три цикла, после чего происходит human escalation).
   После Б тот же цикл повторяется с В, если этап солжный/важный.

И вот с этими возможностями такой флоу:
Есть задача (с нуля или фича для существующего приложения) подаю её на вход.
Агент делает тех-дизайн (тут и на любом этапе далее могут возникнуть открытые вопросы, которые нельзя разрешить кодом и надо уточнить у аналитика/заказчика, по ним сразу посылается сообщение на уточнение и приостанавливается по этой ветке дальнейшая разработка... хотя можно рассмотреть вариант продолжения того, для чего уточнения не нужны). Возможна так-же декомпозиция задачи на создание тех-дизайна, если задача очень сложная.
После - запускается цикл проверки (п.5) для тех-дизайна - скорее всего несколько циклов разными ИИ-агентами.

Далее создаётся файл с разбивкой по таскам. Там-же - граф очерёдности реализации. Так-же проходит цикл(ы) проверки.

Далее - создание таск-планов(~beads) по одному за раз, так-же с циклом(и) проверки.

Далее - ревью уже всех таск-планов скопом, для проверки границ. (так-же с циклом(и) проверки)

Далее - реализация таск-планов (во тут возможно распараллеливание, впрочем оно не так уж и критично) каждая реализация так-же с циклом(и) проверки.

В конце каждой реализации выявляется целесообразность ручной проверки (билд, деплой, проверка через АПИ/CLI/headless browser/etc.) и проводится, если надо. По результатам проверки вносятся необходимые изменения (которые так-же проходят цикл п.5) и проводится повторное ручное тестирование.

Далее проводится общее ревью всех реализованных тасок, параллельно разными агентами. При этом если агент А нашёл фандинги - то он отправляет задачу на правку агенту Б, для правки на его усмотрение. Таким образом - снова цикл получается, просто начинается он с проверяющего.
И таких циклов несвязанных несколько, с разными начальными проверяющими.
