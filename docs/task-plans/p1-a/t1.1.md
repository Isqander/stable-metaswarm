## 2. Цель и наблюдаемый результат

**Цель.** Создать минимальный устанавливаемый Python 3.12-пакет в `src-layout`
с воспроизводимыми dev-зависимостями и одной командой локальной проверки.

**Наблюдаемый результат.** В чистом checkout разработчик выполняет
`./scripts/check.sh`; скрипт использует зафиксированное окружение, запускает
непустой набор `pytest` и `ruff check .`, после чего завершается с кодом 0.

## 3. Границы

**Входит:**

- PEP 621 metadata пакета `stable-metaswarm`, import-пакет `src/metaswarm` и
  ограничение `requires-python = ">=3.12"`;
- build backend `setuptools`, явный `package-dir`/discovery только из `src` и
  пустой список runtime-зависимостей;
- dev-группа с `pytest >=9.1,<10` и `ruff >=0.16,<0.17`, зафиксированная в
  `uv.lock`;
- минимальная конфигурация pytest и Ruff для Python 3.12; Ruff не сканирует
  `fixtures/` и `refs/`, которые не принадлежат production-пакету T1.1;
- один исполняемый POSIX-скрипт, последовательно запускающий pytest и Ruff через
  `uv run --locked`;
- smoke-тест установки дистрибутива и краткая инструкция разработчика.

**Не входит:**

- CLI entry point, Typer и Rich — `T1.19`;
- Pydantic-контракты — `T1.7`, YAML-конфиг — `T1.17`;
- store, миграции и SQLite-код — `T1.2`;
- пустые каталоги `src/metaswarm/{domain,store,agents,effects,service,config,obs}`:
  их создают задачи-владельцы при появлении первого кода;
- изменение или переформатирование `fixtures/vendor-cli/fake-cli.py` — это
  исполняемая фикстура T0.2, исключённая из Ruff scope этой задачи;
- CI, Docker, pre-commit, публикация пакета, coverage и форматтер;
- установка или авторизация vendor CLI.

`uv` выбран здесь как единый dev-tool, потому что он одной парой
`pyproject.toml` + `uv.lock` закрывает резолюцию, создание окружения и запуск с
проверкой свежести lockfile в обеих POSIX-средах. В собранный дистрибутив и
production readiness он не входит. `setuptools` остаётся стандартным build
backend, поэтому сам пакет не зависит от способа, которым разработчик создал
окружение. `src-layout` и явный discovery не дают setuptools принять
`fixtures/` или `refs/` за namespace-пакеты и не позволяют импорту из корня
checkout скрыть неустановленный distribution.

## 8. Порядок реализации

1. Создать `pyproject.toml` с package metadata, build backend, пустым runtime
   dependency set, dev-группой и минимальными настройками pytest/Ruff.
2. Настроить `src-layout` и явный setuptools discovery; добавить корневой пакет
   и smoke-тест, который подтверждает единственный top-level package и читает
   установленную distribution metadata.
3. Сгенерировать и закоммитить `uv.lock`; выполнить `uv sync --locked` в чистом
   окружении Python 3.12.
4. Добавить fail-fast `scripts/check.sh`, выставить executable bit и проверить
   запуск как из корня, так и из другого рабочего каталога.
5. Обновить `.gitignore` и README, затем выполнить позитивные и негативные
   проверки из §10.

## 9. Критерии приёмки

- **AC-1.** При чистом checkout с Python 3.12+ и `uv`, когда выполняется
  `uv sync --locked`, тогда создаётся проектное окружение, distribution
  `stable-metaswarm` устанавливается editable, `metaswarm` импортируется из
  `src`, а `fixtures` и `refs` не объявляются top-level packages дистрибутива.
- **AC-2.** При синхронизированном checkout, когда из корня выполняется
  `./scripts/check.sh`, тогда запускается минимум один pytest-тест, после него
  Ruff, оба завершаются успешно, а итоговый код равен 0.
- **AC-3.** При локально изменённой декларации зависимости без изменения
  `uv.lock`, когда запускается `./scripts/check.sh`, тогда проверка завершается
  ненулевым кодом до выполнения тестов и не переписывает lockfile.
- **AC-4.** При отсутствии `uv` в `PATH`, когда запускается
  `./scripts/check.sh`, тогда stderr объясняет, какой инструмент отсутствует,
  и процесс завершается кодом 127.
- **AC-5.** После реализации в diff отсутствуют CI, Docker, pre-commit, CLI,
  доменные и инфраструктурные заглушки; runtime dependency set остаётся пустым,
  а Ruff scope не захватывает `fixtures/` и `refs/`.
- **AC-6.** При запуске `./scripts/check.sh` не из корня репозитория скрипт сам
  находит корень и выдаёт тот же зелёный результат.

## 11. Риски и откат

| Риск | Ранний сигнал | Что делать | Граница отката |
|---|---|---|---|
| `uv` отсутствует на текущем VPS и может отличаться способом установки в WSL2 | `uv --version` не найден до начала реализации | Установить официальный `uv` как user-local dev-tool в обеих POSIX-средах; если это невозможно или заметно усложняет bootstrap, вернуть общий tooling-контракт и `T1.1` на ревью, не добавлять молчаливый fallback | Git-изменения T1.1 независимы от production state; `.venv` одноразова и не входит в репозиторий |
| Настройка setuptools discovery будет удалена или расширена и снова захватит соседние каталоги | `uv sync --locked` сообщает multiple top-level packages либо metadata показывает package кроме `metaswarm` | Держать одновременно `src-layout`, явные `where/include` и smoke-тест top-level ownership | Откатывается пара `pyproject.toml` + `src/metaswarm` к последней зелёной ревизии |
| Узкие диапазоны dev-tools устареют | Новая версия нужна для исправления или поддержки Python | Обновлять constraint и `uv.lock` одним отдельным проверяемым изменением; `--locked` запрещает частичное обновление | Возврат пары `pyproject.toml` + `uv.lock` к последней зелёной ревизии |
| Будущая задача добавит зависимость заранее или в dev-группу вместо runtime | Импорт появляется в `src/metaswarm/`, но package metadata его не объявляет | Задача, первой использующая библиотеку, одновременно меняет `project.dependencies`, lockfile и тест установки | Откат изменения потребляющей задачи, не T1.1 |

## 12. Допущения и открытые вопросы

**Допущения:**

- `uv` устанавливается стандартным user-local способом и принимается как
  build/dev-инструмент и источник lockfile, но не как runtime-зависимость
  сервиса; его отсутствие в readiness production-процесса не является ошибкой.
- На baseline официальные PyPI-страницы показывают стабильные
  [pytest 9.1.1](https://pypi.org/project/pytest/),
  [Ruff 0.16.1](https://pypi.org/project/ruff/) и
  [setuptools 83.0.0](https://pypi.org/project/setuptools/); выбранные
  совместимые линии поддерживают Python 3.12, а точные версии и транзитивные
  зависимости фиксирует `uv.lock`.
- Distribution пока не публикуется, поэтому версия `0.1.0` обозначает
  внутренний pre-MVP пакет и не вводит release-процесс.
- Поддерживаются только POSIX-среды из решения — WSL2 и Linux VPS; отдельный
  PowerShell-скрипт не нужен.

**Открытые вопросы:** нет.
